## AI-Write（长篇小说 AI 创作台）—— 前端首次落地

**背景**：后端 `back/ai-write` 只有 Spring Boot 4 / Java 21 空壳（MySQL + JPA + Security），没有任何业务代码。依据 `设计文档/设计文档NEW.md`（接口 §6、数据库 §5、页面 §7）+ `设计思考.md`（页面原型 §3、提示词 §4）先把前端做出来。

**技术选型**：Vue 3.5 + TypeScript + Vite 6 + Pinia + Vue Router（hash）。零 UI 库、零 markdown 库、零图标库 —— 图标是内联 SVG 组件，Markdown 自研极简渲染，依赖只有 3 个运行时包。

**产出结构**（`front/`）：
- `src/api/`：按域拆分 9 个模块，全部经 `http.ts` 的 `call()` / `openStream()`，`USE_MOCK` 开关（默认 true）在 mock 与真实 REST/SSE 之间切换。后端就绪只需设 `VITE_USE_MOCK=false`。
- `src/api/mock/`：seed（测试小说《御兽：从一枚灰蛋开始》）+ db（内存库）+ streamText（5 段共 2671 字流式语料，落在 2300—2700 验收区间）。
- `src/stores/`：user / novel / generation（SSE 状态机）/ ui。
- `src/components/common/`：12 个原子组件（含渐变主按钮、无 deprecated 语法的标签、数字滚动 StatCard）。
- `src/components/ai/`：AiPulse、StreamText（打字机光标 + 逐段淡入）。
- `src/views/`：9 个页面（登录、工作台、大纲、卷章纲确认、设定库、三栏创作、审核入库、导出、用量）。

**踩过的坑（记下来）**：
1. rollup 缺 `@rollup/rollup-win32-x64-msvc` 导致 build 失败 —— npmmirror 镜像不装 optional native deps，需手动补。
2. `AppInput` 的 `maxlength` 声明为 number，模板写 `maxlength="30"` 会报 TS2322，必须 `:maxlength="30"`。
3. mock SSE 的 `rt.cursor === 0` 判断会死循环（每次 tick 都重发 segment.started），必须改用 `started[]` 布尔数组标记。
4. 多次 Edit 模板字符串时把结尾反引号 / 数组闭合 `]` 吃掉过两次 —— 改大量文本后用 esbuild.transformSync 做语法校验最省事。
5. Node 环境无 localStorage，`http.ts` 已做 `ls()` 安全降级（顺带 SSR 友好）。

**验证**：`vue-tsc --noEmit` 零报错、`vite build` 通过；`smoke-runtime.mjs`（vite ssrLoadModule 驱动的真实运行用例）27 项全部通过，覆盖乐观锁 409、SSE 五段流转、字数区间、停止/恢复、审核入库事务写回设定库。dev server 端口 5180。


## 下午：后端（MVC 架构，MySQL）

**用户决策**：数据库用 MySQL（不用 PostgreSQL）。原因：本机 MySQL 8 已在 3306 运行、用户另一个项目也在用、MVP 不需要 PG 特性。
MySQL 唯一硬差距是 partial unique index（规则⑦），用**虚拟生成列 + 唯一索引**等价实现，已实测：
- 同章第二个 RUNNING 任务 → ERROR 1062 Duplicate entry for key 'uk_active_chapter'
- 已完成任务 → 允许并存

**架构**：严格 MVC 分层
`controller(HTTP/校验) → service(业务规则) → repository(Spring Data JPA) → model(JPA 实体)`
+ dto(View Model)、config、common、support。共 9 个业务模块：auth/novel/outline/setting/chapter/generation/review/usage/export。

**关键实现**
- SSE：SseEmitter + 事件落库（generation_events，支持 Last-Event-ID 补读）
- ModelGateway：mock（本地语料，无 Key 可跑通）/ openai（DeepSeek 等 OpenAI 兼容）
- 审核 approve：同一事务写回摘要 + 角色状态 + 时间线 + 伏笔
- 乐观锁：content_version，冲突返回 409

**踩坑记录（重要）**
1. **Lombok 静默失效**：只要工程里还有其它编译错误（重复类、找不到包），javac 会跳过注解处理轮次，
   导致 @Getter/@Data 全部不生成，报出漫山遍野的「找不到符号」。先修掉非 Lombok 错误，Lombok 自动恢复。
2. Spring Boot 4 用的是 **Jackson 3**（包 tools.jackson.core），Spring 自己的 ObjectMapper 不在 com.fasterxml 下。
3. 骨架的 parent 是 4.0.10-SNAPSHOT，公共镜像拉不全 starter-validation → 改 4.0.8。
4. `characterEncoding=utf8mb4` 在 Connector/J 9.x 非法 → 必须用 `UTF-8`。
5. 组件不能命名为 requestContextFilter（与 Spring Boot 内置 bean 冲突）。
6. SSE 事件逐条同步落库会把 10 秒的生成拖到 90 秒 → 改成异步单线程落库，任务收尾 await 写完。
7. POST 创建任务后立即开跑，客户端连 SSE 时开头事件已发完 → runAsync 前先等最多 2.5s 让连接建好。
8. mock 语料整段追加会把单章顶到 2831 字（超 2700 上限）→ 按句截断到本段目标字数。

**验证**：mvn compile 通过；MySQL 19 张表；tools/smoke-api.mjs 全链路冒烟 30 项全部通过
（SSE 十秒内完成、字数 2583 在区间、409 乐观锁、幂等、审核入库）；前端 VITE_USE_MOCK=false 已联通真实后端。
本机 MySQL：root / 123456，库 ai_write（写进了 application.yml，上线前改环境变量）。
