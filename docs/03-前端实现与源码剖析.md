## 2. API 层：一个开关切 mock 与真实后端

`http.ts` 是全站唯一的请求入口，两个原语：

```ts
export const USE_MOCK = import.meta.env.VITE_USE_MOCK !== 'false'

/** 普通请求 */
export async function call<T>(method, path, body, mockFn?): Promise<T> {
  if (USE_MOCK) return mockFn()                  // 走内置 mock
  const res = await fetch(BASE + path, {...})    // 走真实 REST
  const json = await res.json()
  if (json.code !== 0) throw Object.assign(new Error(json.message), { code: json.code })
  return json.data as T
}

/** 流式请求 */
export function openStream<T>(opts: OpenStreamOptions<T>): StreamHandle {
  if (opts.mockFactory) { /* mock：由工厂函数驱动 emit */ }
  const es = new EventSource(url)                // 真实：EventSource
  ...
}
```

**设计价值**：后端没就绪时，前端所有交互都是真的（点"AI 拆章纲"真的会返回 18 条章纲），只是数据来自内存。后端就绪后只改 `.env` 一行：

```env
VITE_USE_MOCK=false
```

### 2.1 认证 token 的存取

```ts
function ls(): Storage | null {
  try { return typeof localStorage !== 'undefined' ? localStorage : null }
  catch { return null }
}
export function getToken(): string {
  return ls()?.getItem(TOKEN_KEY) ?? memoryToken[TOKEN_KEY] ?? ''
}
```

> 这个"降级到内存"的写法不是炫技：Node 环境（冒烟脚本用 SSR 加载器跑 API）没有 `localStorage`，不降级会直接崩。

登录成功后必须存 token（真实模式）：

```ts
login(payload).then((profile) => {
  if (!USE_MOCK && profile?.token) setToken(profile.token)
  return profile
})
```

### 2.2 SSE 的 URL 与 token

`EventSource` 不能带请求头，所以 token 走 query —— 后端 `TokenAuthenticationFilter` 专门支持了这条通道：

```ts
const url = `${BASE}${path}?token=${encodeURIComponent(getToken())}`
```

## 3. 类型系统：前后端契约的钉子

`types/index.ts`（343 行）定义了全部领域模型。举两个关键的例子：

```ts
/** 章节：字段与后端 ChapterDto 一一对应 */
export interface Chapter {
  id: number; novelId: number; volumeId: number; outlineId: number | null
  chapterNo: number; title: string
  contentMd: string; wordCount: number
  chapterStatus: 'OUTLINED' | 'GENERATING' | 'REVIEW_PENDING' | 'APPROVED'
  auditStatus: 'NOT_RUN' | 'DRAFT' | 'PASSED' | 'NEEDS_REVIEW'
  contentVersion: number
  createdAt: string; updatedAt: string
}

/** SSE 事件：与后端 emit() 的 payload 对齐 */
export interface GenerationStreamPayload {
  type: 'job.started' | 'segment.started' | 'text.delta'
      | 'segment.completed' | 'chapter.draft_ready'
      | 'job.completed' | 'job.stopped' | 'job.failed'
  payload: Record<string, unknown>
}
```

**为什么值得**：后端把 `ChapterDto` 的字段改名，前端 `vue-tsc` 立刻报错，不用等到用户点开页面才白屏。本项目在联调中就是靠它提前发现了导出接口的契约不匹配。

## 4. 状态管理：三个 store 的分工

| store | 管什么 | 关键点 |
|---|---|---|
| `user` | 登录态、profile、配额百分比 | `load()` 失败（401）时清空 profile，但不强制跳登录 |
| `novel` | 作品/卷/章纲/章节/设定库，以及**前置校验** | `canGenerate(chapter)` 把规则①②⑦翻译成前端按钮的禁用态 |
| `generation` | SSE 状态机、分段进度、流式文本缓冲 | 全站最复杂的状态，见下 |

### 4.1 generation store：一个手写的状态机

```ts
type StreamStatus = 'IDLE' | 'CONNECTING' | 'RUNNING' | 'STOPPED' | 'COMPLETED' | 'FAILED'

const buffers = ref<Record<number, string>>({})   // 每段累积的文本
const mergedText = computed(() =>                // 按段号顺序拼成整章
  Object.keys(buffers.value).sort((a,b)=>+a-+b).map(k => buffers.value[+k]).join('\n\n'))
const wordCount = computed(() => countWords(mergedText.value))
const percent  = computed(() => Math.min(100, Math.round((wordCount.value / targetWords.value) * 100)))
```

事件回调如何驱动状态：

```ts
onDelta: (segNo, text) => {
  buffers.value[segNo] = (buffers.value[segNo] ?? '') + text
  const idx = segments.value.findIndex(s => s.segmentNo === segNo)
  if (idx >= 0) segments.value[idx].written = countWords(buffers.value[segNo])
},
onStopped: () => {
  status.value = 'STOPPED'
  segments.value.forEach(s => { if (s.status === 'RUNNING') s.status = 'INCOMPLETE' })
}
```

**为什么用 `buffers` 而不是一个长字符串**：stop/resume 时后端会重发某些段；按段号分桶存储，天然支持"某段被重发就覆盖该段"而无需担心错位。

### 4.2 前端的字数统计必须与后端一致

```ts
export function countWords(text: string): number {
  // 中文字符 + 英文单词 + 数字串，标点不计
}
```

后端 `TextKit.countWords` 是同一套口径。否则会出现"前端显示 2540 字、后端判定 2510 字"的鬼故事。测试 `TextKitTest` 把口径固定了下来。

## 5. 流式渲染：打字机是怎么做出来的

`components/ai/StreamText.vue`：

### 5.1 自研 Markdown 渲染（25 行）

```ts
const html = computed(() => {
  const escape = (s: string) => s.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;')
  return src.split(/\n{2,}/).map((block) => {
    const line = block.trim()
    if (/^#{1,6}\s/.test(line)) { /* 标题 */ }
    if (/^(-{3,}|\*{3,})$/.test(line)) return '<hr/>'
    const isQuote = line.startsWith('>')
    const body = escape(...)
      .replace(/\*\*([^*]+)\*\*/g, '<strong>$1</strong>')
      .replace(/\*([^*]+)\*/g, '<em>$1</em>')
      .replace(/`([^`]+)`/g, '<code>$1</code>')
      .replace(/\n/g, '<br/>')
    return isQuote ? `<blockquote>${body}</blockquote>` : `<p>${body}</p>`
  }).join('')
})
```

**为什么不用 marked**：小说正文只需要 4 种语法。引入 marked（~40KB）+ DOMPurify（~45KB）只为这 25 行不划算，还多一个 XSS 面。这里先 `escape()` 再补标签，**顺序不能反**。

### 5.2 打字机光标与段落淡入

```html
<div class="reader" :class="{ serif, typing }">
  <div v-if="html" class="md" v-html="html" />
  <span v-if="typing" class="caret" aria-hidden="true" />
</div>
```

```css
.md :deep(p) { text-indent: 2em; animation: fade-in 500ms var(--ease-out) both; }
.caret { animation: caret-blink 1s step-end infinite; }
```

- 正文段落用 `text-indent: 2em` —— 中文小说排版习惯；
- 每段 `fade-in` —— 新段出现时不闪；
- `typing` 时显示闪烁光标 —— 让用户确信"还在写"，比转圈更贴合写作场景。

### 5.3 自动滚动

`WriterView.vue` 里：生成时正文容器自动滚到底部，但给了用户一个"自动滚动"开关（正在人工编辑时不该被强行滚动）。

## 6. 组件设计：自己造轮子

### 6.1 图标系统（34 个手写 SVG）

```vue
<!-- AppIcon.vue：按名取用，颜色/尺寸跟随上下文 -->
<AppIcon name="sparkle" :size="16" color="var(--brand)" />
```

图标名清单：`outline write settings export usage review plus close check edit trash sparkle play pause stop refresh book user users globe clock link palette arrowRight arrowLeft chevronDown chevronRight chevronLeft search logout folder file upload download drag filter bolt shield warning info`

全部内联 `<path>`，靠 `currentColor` 跟随主题。代价是画图标要手工（从 Figma 或 Iconfont 取 path），收益是零依赖 + 完全可控。

### 6.2 主按钮的渐变与光效

`AppButton.vue` 用伪元素做悬停光扫：

```css
.btn.primary { background: var(--grad-brand); box-shadow: var(--sh-brand); }
.btn:hover  { transform: translateY(-1px); }
.btn:active { transform: translateY(0) scale(.985); }
```

12 个 variant（primary / outline / soft / ghost / danger …）、3 个尺寸、支持 `icon` / `loading` / `block`。

### 6.3 统计卡的数字滚动

`StatCard.vue` 用 `requestAnimationFrame` + easeOut 做数字从 0 滚到目标值，配合进度条与 hint 文案。首屏 4 张卡有 40ms 的 stagger 延迟，形成"依次亮起"的效果。

### 6.4 进度条支持三种形态

`AppProgress.vue`：`bar`（条）、`ring`（SVG 环形，用 `stroke-dasharray`）、`striped`（带流动斜纹）。创作台右侧的"字数校验环"就是 ring 形态。

### 6.5 其它

| 组件 | 关键实现点 |
|---|---|
| `AppModal` | Teleport 到 body + 焦点管理 + Esc 关闭 |
| `AppTabs` | 滑动指示条（transform 跟随激活项） |
| `AppTag` | 用 `rgba(var(--tone), .12)` 做半透明底色，避免为每个语义色写一份 class |
| `AppSkeleton` | 骨架屏，加载态不跳版 |
| `ToastHost` | 全局轻提示，支持 success/warn/error/info |
| `AppEmpty` | 空态（带图标 + 说明 + 行动按钮），比空列表友好 |

## 7. 样式与动效系统

### 7.1 CSS 变量（一处改，全站变）

```css
:root {
  --brand: #6366f1;  --brand-strong: #4f46e5;
  --pink: #ec4899;   --purple: #a855f7;  --cyan: #22d3ee;
  --grad-brand: linear-gradient(135deg, #6366f1 0%, #a855f7 45%, #ec4899 100%);
  --sh-brand: 0 8px 22px -6px rgba(99,102,241,.55);
  --r-sm: 8px; --r-md: 12px; --r-lg: 16px;
  --dur-fast: 140ms; --dur-base: 220ms; --dur-slow: 340ms;
  --ease-out: cubic-bezier(.22,1,.36,1);
  --ease-spring: cubic-bezier(.34,1.56,.64,1);
}
```

### 7.2 动画清单

| 动画 | 用在哪 |
|---|---|
| `fade-up` | 卡片/列表入场 |
| `fade-in` | 正文段落、标签 |
| `pop-in` | 勾选框、徽标 |
| `shimmer` | 卡片悬停光扫 |
| `float-y` | Logo 浮动 |
| `roam` | 登录页背景光斑飘移 |
| `caret-blink` | 打字机光标 |
| `pulse-ring` | AI 呼吸光环（生成中） |

原则：**动效服务于状态表达**（生成中、加载中、成功、冲突），不是装饰。所有动效时长 ≤ 340ms，避免拖沓。

### 7.3 两套字体

正文用衬线体（小说阅读感），UI 用无衬线体，代码/数字用等宽体。

### 8.1 创作台（WriterView）值得单独看

三栏布局用 CSS Grid：

```css
.writer { display: grid; grid-template-columns: 234px minmax(0,1fr) 300px; height: 100%; }
```

- **左**：章节树，点击切换（生成中禁止切换，避免状态错乱）
- **中**：顶部状态栏（AI 呼吸指示 + 字数 + 版本）+ 五段进度 + 正文/编辑切换 + 底部自检/审核
- **右**：本章 beat、本章引用设定（可展开看卡面）、最近自检结果、字数校验环、**不可生成时显示原因**

右侧的"当前不可生成"提示直接复用后端的校验逻辑（`novelStore.canGenerate`），把规则①②⑦的结果翻译成人话展示给用户 —— 这比"按钮灰了但不知道为什么"体验好得多。

## 9. 前后端契约对照表

| 前端调用 | 后端 | 对齐要点 |
|---|---|---|
| `novelApi.list()` | `GET /api/novels` | `NovelDto.stats` 与前端 `NovelStats` 字段一致 |
| `chapterApi.saveContent(id, md, v)` | `PUT /api/chapters/{id}/content` | body `{contentMd, expectedVersion}` |
| `generationApi.start(cid, key)` | `POST /api/chapters/{id}/generation-jobs` | 202 + `{jobId,...}` |
| `generationApi.openEventStream(jid)` | `GET /api/generation-jobs/{id}/events` | 帧体 `{seq, type, payload}` |
| `reviewApi.draft(id)` | `POST /api/chapters/{id}/review-draft` | `{issues, summary, changes}` |
| `reviewApi.approve(id, req)` | `POST /api/chapters/{id}/approve` | `{summary, changes}`（changes 带 `accepted`） |
| `exportApi.run(id, opt)` | `GET /api/novels/{id}/export/meta` | ⚠️ 不能调 `/export`（二进制流） |
| `exportApi.downloadUrl(id, opt)` | `GET /api/novels/{id}/export` | token 走 query |
| `usageApi.overview()` | `GET /api/usage` | `{monthCost, monthTokens, chapterThisMonth, budget, byScene, records}` |

> 导出那条是真实踩过的坑：一开始前端直接调 `/export` 期望 JSON，结果拿到 docx 二进制流，报"服务端返回了非 JSON 响应"。修法是拆成 `/meta`（JSON）+ `/export`（下载）两个入口。
